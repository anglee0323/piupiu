# Piupiu 架构与约定（骨架）

这份文档回答两个问题：**系统由哪几块组成**，以及**哪些地方可以随便改、哪些地方不能随便动**。新功能、重构、翻译、贡献代码前先读它。

## 0. 文档分工

| 文档 | 给谁看 | 写什么 | 公开 |
|---|---|---|---|
| `README.md` | 使用者 / 自部署的人 | 是什么、怎么安装运行、配置项、安全模型 | 是 |
| `docs/ARCHITECTURE.md`（本文） | 贡献者 / 维护者 | 分层、稳定契约、可变部分、中英文规则 | 是 |
| `docs/self-hosting.md` | 自部署的人 | 运行环境、节点与数据源、运行模式、安全 | 是 |
| `docs/PLAN-*.md`、`AGENTS.md`、`cloud/` | 只有维护者 | 施工记录、单个功能的设计取舍、官网、发布上传、域名、收费与商业决策 | 否 |

仓库：维护者在私有仓库开发（含上面不公开的部分）；公开仓库 `anglee0323/piupiu` 由 `scripts/export-oss.mjs` 从私有仓库导出（不收手续费、不内置数据源、不含不公开的部分），每次发内核时同步。公开仓库收到的 PR 由维护者合入私有仓库后再同步回来。

原则：**公开仓库里不出现任何私有信息**；导出时会扫描作者钱包、本机路径、云账号和内置数据源，命中就中止。

## 1. 分层

```
入口（只负责显示和点击）            网关（判断与执行，唯一能动钱的地方）
  桌面 App 的界面  web/      ─┐
  以后：Telegram 自建 Bot     ├──  HTTP /api/* + WebSocket  ──  server.js + engine/
  以后：浏览器插件            ─┘                                    │
                                                                    ├─ 币安钱包命令行（baw，登录只在本机）
共用：shared/（筛选规则、能力开关、以后的中英文字典）               ├─ 链上节点、发射台公开接口
外壳：desktop/（启动网关、窗口、签名自动更新）                      └─ 可选数据服务（X 讨论等，官方版连我们的服务）
```

- **网关**（`server.js`、`engine/`）：所有判断（提醒、自动化条件、风控）和所有执行（下单、铸造、转出）都在这里。界面不做业务判断。
- **shared/**：网关和界面共用的纯函数与常量，不依赖 Node 或浏览器专有 API。
- **界面**（`web/`）：React，只呈现网关给的数据、把用户操作发给网关。
- **外壳**（`desktop/`）：Electron。随机端口启动网关、加载界面、自动更新；不含业务逻辑。
- **在线体验**（`web/` 的 demo 构建，`vite --mode demo`）：官网 `/preview/` 用的同一套界面，没有网关，读录制的行情样本，不能连接钱包或下单。录制和发布在私有仓库。

## 2. 不能随便动的（稳定契约）

每一条都写了「确实要改时怎么改」。

1. **安全底线**（不改）
   - 钱包登录凭证只保存在用户本机，不发送给任何服务器；我们不托管任何会话。
   - 交易由币安钱包签名，Piupiu 不接触私钥；发版签名私钥不进任何仓库。
   - 会自动动用资金的功能：默认关闭、开启前确认、有次数或金额上限、列入 `GET /api/automation`。
2. **网关 API**（HTTP `/api/*`、WebSocket 消息类型与字段）
   - 只增不改：可以加接口、加字段；不改已有字段的含义，不删。
   - 必须删改时：先加新接口，旧的保留至少一个版本并标注弃用。所有入口（界面、Bot、插件）都依赖它。
3. **本地数据格式**（`<用户目录>/data/`）
   - 界面设置 `prefs` 有版本号，结构变化时版本 +1 并写 `migrate`。
   - `radar/mints.jsonl` 只追加；钱包会话目录结构（`wallets/w<N>/baw`）不改。
   - 改格式必须能读旧数据，并在更新说明里写清楚。
4. **更新通道**
   - 签名清单格式（`core.json` / `shell.json` + `.sig`）、App 内置公钥、`updateBase`。
   - 换更新地址用签名清单的 `moveTo` 迁移；**换签名钥匙等于所有用户重新安装**，不做。
5. **能力开关**（`shared/capabilities.js`）：受币安限制、暂不可用的功能统一在这里关，界面和网关同时生效。
6. **文案键**（中英文字典的键，见第 4 节）：发布后不改名；要改措辞只改字典里的值。

## 3. 可以自由改的

- 界面布局、样式、交互（遵守 `AGENTS.md` 里的对齐、SettingsKit、数字输入等约定）。
- 文案措辞（改字典的值；中英文同时改）。
- 雷达评分与结论规则（改完 `ANALYSIS_VER` +1，旧分析会自动重跑）。
- 网关内部模块的拆分与实现，只要对外 API 和数据格式不变。
- 新功能：放进现有分层（判断在网关、显示在界面、共用规则在 `shared/`）。

## 4. 中英文

**目标**：顶部栏右侧可切换「中 / EN」，所有界面文字和网关返回给用户的提示都跟随切换；以后加语言只加一份字典。

- **语言**：`zh`（默认）、`en`。选择存在界面设置 `prefs.lang`，同步给网关。
- **字典**：`shared/i18n/zh.js`、`shared/i18n/en.js`，网关和界面共用一份。
  - 键按区域命名：`nav.trenches`、`trade.buy`、`err.walletNotLoggedIn`、`radar.soon.title`。
  - 带参数用占位符：`'已创建 {n} 个条件单'`；数字、金额、时间用 `Intl` 按语言格式化。
  - `en` 必须覆盖 `zh` 的全部键，测试检查。
- **界面**：`t('key', params)`；不再在组件里直接写中文。
- **网关**：返回给用户的报错、订单原因、使用前检查等用同一套 `t()`，按 `prefs.lang` 生成；日志（控制台、`wallet-events.log`）保持中文，不翻译。
- **雷达结论**：中文原文照旧保存（旧代码按原文判断）；同时带文案键和参数（评分条目、列表理由、配方原因、用途编号），简介与风险提示另存英文版 `reviewEn`。界面英文按键显示，没有键的旧数据退回原文。
- **不翻译**：代币名、合约地址、推文原文、第三方接口返回的原文。
- **防回归**：测试扫描 `web/src` 和网关的用户文案，禁止新增硬编码中文（存量用白名单，逐步缩小）。
- **分阶段**：
  1. 框架、切换入口、顶部栏、底栏、设置、提示。
  2. 各页面。
  3. 网关报错与订单原因。
  4. 雷达结论。

## 5. 新功能自查

- 判断和执行在网关，界面只显示？共用规则在 `shared/`？
- 动钱吗？默认关、开启确认、有上限、列入 `/api/automation`？
- 改了 API 或数据格式？只增不改，或写了迁移？
- 新文案进字典了吗？中英文都有？
- 测试、构建、冒烟（`npm test`、`npm --prefix web run build`、`node scripts/smoke.mjs`、界面冒烟）都过了吗？
